# 译文 SRT 生成器（离线工具）

用**已有的 SRT（任意语言，只借它的时间轴）** + **译文电子书**，生成译文字幕。

它不是播放器的一部分，是一个独立的离线脚本：不联网、不调用翻译接口、不依赖第三方库。
适用场景：有声书是日文录音，你手上有日文 ASR 字幕（时间轴可用、文本有错、断句随意），
同时有中文版电子书。这个工具把两者拼起来，输出中文 SRT。

## 用法

```powershell
python tools\srt-align\srt_align.py "<有声书目录>"
```

参数：

| 参数 | 说明 |
| --- | --- |
| `target` | 目录（自动找 srt / epub / m4b），或单个音频 / srt 文件 |
| `--srt` | 指定源 SRT（默认自动找最大的、且不是 `.zh.srt` 的） |
| `--book` | 指定译文 epub |
| `--out` | 输出路径（默认同名的 `.zh.srt`） |
| `--report` | 额外输出逐条对齐明细，便于人工抽查 |

例：

```powershell
python tools\srt-align\srt_align.py "D:\有声书\某本书" --report .\report.txt
```

## 原理（为什么不需要翻译模型）

中文字幕的时间轴必须来自 ASR，文本必须来自电子书——两者语言不同、没有词汇交集，
所以只能靠**结构**对齐。工具用到三种信号：

1. **章节锚点** —— 优先读音频文件自带的章节表（m4b 的 `chpl`、`m3u8` 播放列表），
   把整本书切成块，误差不会跨章累积；没有锚点就按等价时长自动切块。
2. **章节归属** —— 音频章节名与电子书章节名按「序章 / 第N章 / 终章 / 后记」模式匹配；
   对不上的中间章节按顺序 + 时长/字数比例插值；**两端的锚点（片头广告、片尾演职员）故意不配对**。
3. **段句对齐** —— 每段的期望译文字数 =
   `0.7 ×（该段源语言字数 × 全章字数比）+ 0.3 ×（时长 × 译文字/秒）`，
   然后做单调 DP，允许一段吞 0–6 句、允许章首/章尾若干段不分配文本。

第三条里的"允许首尾留空"就是通用地吸收**片头广告、念书名/章节名、片尾**这些书里没有的内容——
不需要认识任何具体书名或关键词。

## 可选：句向量语义对齐（精度 88% → 93%+）

纯长度对齐在对话密集处会偏一句。加上多语言句向量模型后，DP 里多一项「这一段和这一句
语义有多像」，精度显著提升——仍然不调用翻译接口。

```powershell
rem 一次性安装（torch 走 CUDA 版，约 2.7 GB）
python -m venv .venv
.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cu128
.venv\Scripts\python -m pip install sentence-transformers

rem 跑的时候指定模型目录（本地快照路径或 HF 名都行）
.venv\Scripts\python srt_align.py "<目录>" --embed "D:\...\_models\...\snapshots\xxxx"
```

| 参数 | 说明 |
| --- | --- |
| `--embed MODEL` | 启用语义对齐（本地路径或 `BAAI/bge-m3`） |
| `--sim-weight N` | 语义权重，默认 **2.0**（0 = 纯长度；2–3 最好，更大开始回落） |
| `--device cuda/cpu` | 默认自动 |

实测（人工译文当标准答案，化物語 上/中/下 共约 2.7 万条）：

| 书 | 纯长度 完全相同 | +bge-m3 完全相同 | 平均相似度 |
| --- | --- | --- | --- |
| 01 上 | 88.7% | **93.5%** | 0.972 |
| 02 中 | 92.4% | **95.1%** | 0.990 |
| 03 下 | 88.4% | **92.6%** | 0.971 |

实现要点（踩过的坑）：

- **余弦要先按行做 z-score**：正确对 0.46–0.93、错配 0.27–0.58，原始分数区间重叠；
  归一化成"这一行里哪句最像"的相对信号才稳定。
- **不能按比例把长章切成小块**：真实句子会落到窗口外（实测未分配率从 0.3% 涨到 5%）。
  正确做法是整章一次 DP，用**带宽**限制搜索范围。
- **长度项非对称**：超额分配（一句字幕塞太多字）罚两倍，否则语义项会盖过长度项，
  产出一堆读不过来的字幕。
- bge-m3 权重是 `pytorch_model.bin`（不是 safetensors）；国内用 `HF_ENDPOINT=https://hf-mirror.com`。

## 输出

标准 SRT：时间轴来自源 SRT，文本来自电子书，长句按标点拆分为多条。
运行结束会打印体检数据：用掉的译文句数、时间轴范围、>20 秒的空隙数、过密行数量。

## 基准测试

```powershell
python bench.py "<某本书的目录>"            # 纯长度
python bench.py "<目录>" --embed <模型路径>  # 语义对齐
```

它把人工 `.zh.srt` 按章节包成临时 epub，用真实时间轴跑完整流水线，再逐条比对——
所以上面的百分比可以用你自己的书复现。

## 已知边界

- 纯长度对齐在同一章内局部可能有 ±1–2 句偏移；启用句向量后差距缩小到约 5–7% 的句子仍会偏一句。
- 电子书的章节标题必须能被「序章/第N章/终章/后记」这类模式识别；识别不出的书会退化为
  "按顺序 + 比例"整体对齐（仍可用，但章节边界不如前者准）。
- 译文必须与录音**同一版本**。如果电子书是删节版/不同译本，比例会逐渐漂移。
- 语义对齐依赖模型质量：专有名词密集的句子仍可能匹配失败，这些位置会退回长度先验。
